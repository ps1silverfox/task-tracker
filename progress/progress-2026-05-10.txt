## 5|INIT-05|PASS
+.env.example,lib/composer.json,lib/src/Config/Env.php,lib/tests/Config/EnvTest.php,TASK.md
verify: exit 0
commit: 86ce15f
learn: `Dotenv::createImmutable($path)` in phpdotenv 5.6 uses only EnvConst+ServerConst adapters by default — it ignores putenv'd values, so a shell-exported var (visible only via getenv()) gets silently overwritten by `.env`. Fix: build the repo manually with `RepositoryBuilder::createWithDefaultAdapters()->addAdapter(PutenvAdapter::class)->immutable()->make()` and pass to `Dotenv::create($repo, $dir)`. Test `testRealEnvOverridesDotenv` caught this — putenv-only simulation matches how Apache sets vhost env (it lands in $_SERVER, but also how shell exports look to PHP-FPM with `variables_order` excluding E). Also: adding a new dep to lib/ uses `composer update <pkg>` (manifest already edited by the +m step) rather than `composer require` (which double-edits composer.json).
