## 4|LIB-04|PASS
+lib/src/Storage/CsvStore.php,lib/tests/Storage/CsvStoreTest.php,TASK.md,AGENTS.md
verify: exit 0
commit: bd5ca9c
learn: The spec's `flock($fh, LOCK_EX)` on the data file + `rename($tmp, $csvPath)` pattern is a POSIX-ism that breaks on Windows NTFS — `rename()` over an open handle returns Access Denied (code 5). Fix: lock a sidecar `<path>.lock` instead, keep the data file closed across the rename. Same lockfile is used by `readAll` (LOCK_SH) so readers serialise correctly against in-flight writes without ever opening the destination. Secondary gotcha: `fgetcsv` treats a non-quote first byte as the start of an unquoted field, so a leading UTF-8 BOM contaminates header[0] as the literal `[BOM]"ID"` — strip the BOM from the byte stream BEFORE the first `fgetcsv()` call, not from the parsed cell. Both patterns recorded in AGENTS.md (windows-rename-needs-sidecar-lock, fgetcsv-bom-and-rfc4180) for future iterations doing storage work.

learn: The two-write audit invariant (CSV first, NDJSON second, no rollback on NDJSON failure) forces an ordering decision: the repository emits events *after* `CsvStore::txn()` returns, not from inside the mutator closure. ## 10|REPO-04|PASS
+lib/src/Repositories/DependencyRepository.php,lib/tests/Repositories/DependencyRepositoryTest.php,TASK.md
verify: exit 0
commit: c0b44f9
learn: Cycle prevention must run *inside* the CsvStore::txn closure, not before it — otherwise a concurrent add between the read-for-DFS and the write-of-edge could close a cycle that our pre-read couldn't see (TOCTOU). The exclusive flock on `<csv>.lock` already serialises writers; piggybacking the DFS on the same critical section costs nothing and removes the race window entirely. Edge semantics from spec §5: row `(TASK_ID=A, PREREQ_ID=B)` means "B is a prerequisite of A" / "B blocks A"; the adjacency map for cycle detection is therefore `requires[task] = list<prereq>`. DFS from the *new prereq_id* (asking "can this prereq reach the task?") is correct — opposite direction is a common bug. Self-edge (A→A) is the degenerate cycle; algorithmically the DFS catches it at depth 0, but an early `if ($taskId === $prereqId) throw 'would create cycle'` skips the empty-file CsvStore round-trip — verified by the `no CSV file written` assertion. No `Dependency` model was scaffolded by MODEL-01 (rows are just a pair of UUIDs), so the repo defines its own `public const HEADERS` and returns plain associative arrays — keep that pattern for any future join-table repositories (TagRepository in REPO-05). Closed action enum admits only `dependency.added` / `dependency.removed` — there is no update event because edges are immutable; modifying an edge is `remove + add`. remove() is idempotent (no event when absent) to support clean replays from the activity feed; add() rejects duplicate composite keys with a distinct "duplicate dependency" message so callers can distinguish "already there" from "would close a cycle".
