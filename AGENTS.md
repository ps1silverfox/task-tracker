# AGENTS.md — patterns Ralph iterations must know

<p id="php-path">PHP 8.3.29 lives at `/c/php/php.exe` and is NOT in the shell PATH. Composer lives at `/c/php/composer` (a phar — invoke as `/c/php/php.exe /c/php/composer ...`). Before running any `!v` command that invokes `php` or `composer`, prepend it: `PATH="/c/php:$PATH" <cmd>`. The CLAUDE-CONTEXT.md "PHP must be in PATH" assumption is false in this Git Bash environment.</p>

<p id="gitignore-scoped-to-root">Root `.gitignore` patterns are anchored (`/composer.lock`, `/.phpunit.cache/`, `/vendor/`), so `composer install` inside `lib/` or `apps/*/` produces `lib/composer.lock` and `lib/.phpunit.cache/test-results` that ARE NOT ignored. Until INIT-06 broadens the ignore rules, every `composer install` iteration must `git restore --staged` those artifacts after `git add` or use explicit per-file `git add` instead of `git add <dir>/`.</p>

<p id="gpg-sign-flag">`commit.gpgsign` and `user.signingkey` are unset in this repo. Do NOT pass `-c commit.gpgsign=false` to `git commit` — it's a forbidden bypass per Bash-tool rules, and a no-op here since signing isn't configured. Plain `git commit -m "..."` is correct.</p>

<p id="path-repo-stability">The `lib/` path repository (`task-tracker/core`) is unversioned, so Composer resolves it only as `dev-main`. With `"minimum-stability": "stable"`, the bare `"task-tracker/core": "*"` constraint fails ("does not match your minimum-stability"). Use the per-constraint stability flag: `"task-tracker/core": "*@dev"`. This keeps the project globally stable for Slim/PHPUnit/etc. while permitting the in-tree dev package. Apply identically in `apps/admin/`, `apps/public/`, and any future `tools/` composer.json.</p>

<p id="phpdotenv-putenv-adapter">`Dotenv::createImmutable($path)` in phpdotenv 5.6 includes ONLY EnvConstAdapter + ServerConstAdapter — it ignores putenv'd values. A shell-exported var visible only via `getenv()` (e.g. when PHP's `variables_order` excludes `E`) will be silently overwritten by `.env`. When loading `.env` anywhere in this codebase, build the repository explicitly: `RepositoryBuilder::createWithDefaultAdapters()->addAdapter(PutenvAdapter::class)->immutable()->make()` and pass to `Dotenv::create($repo, $dir)`. See `lib/src/Config/Env.php`.</p>

<p id="composer-add-new-dep">When a task's `+m` step modifies `composer.json` to add a new dependency, run `composer update <pkg>` (not `composer require <pkg>`). `composer require` would double-edit the manifest, conflicting with the manual edit. `composer update <pkg>` only updates the lockfile + vendor for that one package and leaves the manifest as Ralph wrote it.</p>

<p id="windows-rename-needs-sidecar-lock">On Windows NTFS, `rename()` to a target with any open handle fails with "Access denied (code: 5)". `flock()`ing the data file itself (e.g. `flock(fopen($csvPath, 'c+'), LOCK_EX)`) and then `rename($tmp, $csvPath)` is therefore broken on Windows even though it's idiomatic on POSIX. `CsvStore` locks a sidecar `<path>.lock` file instead, opens the data file briefly for read, closes it, then renames. Any future code doing atomic-rename-over-existing on Windows must follow the same sidecar-lock pattern — never hold the destination file open across the rename.</p>

<p id="fgetcsv-bom-and-rfc4180">PHP 8.3 `fgetcsv` defaults `$escape` to `"\\"` (non-RFC-4180) and triggers a 8.4 deprecation. Pass `escape: ""` for strict RFC 4180 (doubled-quote escaping only). Separately, fgetcsv treats a non-quote first byte of a field as the start of an *unquoted* field — so a leading UTF-8 BOM contaminates the first cell as `[BOM]"ID"` (literal quotes included) rather than being absorbed. Strip the 3-byte BOM from the stream BEFORE the first `fgetcsv()` call, not after.</p>

<p id="tools-dual-mode-cli">Files under `tools/` (seed.php, and future migrate.php, reconcile.php, rotate-logs.php) must expose their work as a callable function in the global namespace AND a CLI dispatch block guarded by `PHP_SAPI === 'cli' && realpath((string)$_SERVER['argv'][0]) === __FILE__`. This lets `tests/integration/*Test.php` `require_once` the file and drive the function in-process (fast, deterministic, assertable on return value) without shell_exec. The `realpath()` guard distinguishes "invoked as script" from "loaded via require_once under phpunit" — phpunit's `argv[0]` is the phpunit binary, never the tool path. Follow `tools/seed.php` (`tt_seed()`) as the template.</p>

<p id="slim-no-static-route-handlers">Slim 4's `CallableResolver::bindToContainer()` calls `Closure::bind($fn, $container)` on every route callable so handlers can access `$this->container`. PHP 8's `Closure::bind()` returns `null` for `static` closures AND triggers a "Cannot bind an instance to a static closure" warning; Slim then throws a `TypeError` because `bindToContainer()` declares `: callable`. With `phpunit failOnWarning="true"` the test suite goes red. NEVER declare route handlers as `static fn`/`static function` — plain `function(...)` or non-static arrow `fn(...)` is required. Applies to every controller created in ADMIN-02..ADMIN-08 and PUB-02..PUB-08.</p>

<p id="lib-path-repo-snapshot-staleness">The `lib/` path repository uses `"symlink": false` (forced because Windows hard-link semantics are unreliable across volumes). Composer therefore copies a SNAPSHOT of `lib/` into each consumer's `vendor/task-tracker/core/` at install time. Adding files under `lib/src/` (e.g. INIT-05's `Config/Env.php`) makes the consumer's snapshot stale — `class_exists()` returns false even though the source is present. After ANY change to `lib/src/`, run `composer update task-tracker/core --no-interaction` inside `apps/admin/`, `apps/public/`, and any other consumer before running their tests. Symptom: PHPUnit reports `Error: Class "TaskTracker\Foo" not found` despite the class existing in `lib/src/Foo.php`.</p>

<p id="repos-take-camelcase-form-keys-are-controller-only">Every `*Repository::create()` / `::update()` in `lib/src/Repositories/` accepts camelCase keys (`dueDate`, `assigneeId`, `effortHours`, `parentId`, `teamId`). Snake_case translation lives ONLY in admin controllers' `normalizeInput()` / `normalizeUpdateInput()`. Unknown keys are SILENTLY DROPPED (no exception, no warning) — they become null in the resulting model. Any test, service, or tool that drives a repository directly with `due_date`, `assignee_id`, `effort_hours`, etc., will pass with a partially-null row and surface as an unrelated assertion failure downstream. Write repo-direct callers in camelCase; reserve snake_case for controllers and seed/test fixtures that round-trip through the controller layer.</p>

<p id="controllers-require-bootstrap-registration">TASK.md `+f apps/{admin,public}/src/Controllers/*.php` rows implicitly require `+m apps/{admin,public}/src/Bootstrap.php` even when not listed. The custom PSR-11 container in `Bootstrap.php` has NO auto-wiring, so Slim 4's `CallableResolver` cannot construct `[ControllerClass::class, 'method']` route callables — it falls back to `new ControllerClass()` and TypeErrors on the missing repo arg. Every new controller MUST be added to the `factories()` array. Also: enable body parsing once via `$app->addBodyParsingMiddleware()` (innermost, before routing) so form-urlencoded/JSON POSTs deliver a parsed array to handlers in production; tests using `withParsedBody()` bypass it and pass either way. Order in Bootstrap::boot must remain BodyParsing → Routing → Error (last added is outermost).</p>

<p id="twig-html-attr-mangles-urls">Twig's `|e('html_attr')` filter escapes every non-alphanumeric byte (including `=`, `&`, `?`, `,`) using `&#xHH;`, which corrupts URL-shaped values placed in `data-*` attributes — a client-side `fetch(canvas.getAttribute('data-json-url'))` then hits a 404. For URLs in attribute positions, rely on the project-wide `autoescape='html'` default (only escapes `& < > " '`) by writing `{{ url }}` without an explicit filter. Reserve `html_attr` for free-form text that may legitimately contain quotes/spaces (e.g. JSON blobs in `data-labels` on summary.twig). Pattern verified: graph.twig data-json-url + GraphController query passthrough test.</p>

<p id="audit-log-preserves-pre-update-fields">The two-write audit invariant means the NDJSON activity feed permanently retains the field values that existed *before* every update (`task.created` carries the original `title`, `task.updated` carries the changed `fields` list, etc.). Therefore an integration test that mutates a field and asserts the public detail page no longer contains the old value will always fail — the old value survives in the `<span class="data">` payload of historical `<li data-action="...">` rows. Assert the current state via positional patterns (`<h1>...</h1>`, `<title>...</title>`) instead of `assertStringNotContainsString`. Encountered while writing AdminPublicSharedDataTest::testAdminUpdateIsReflectedInPublicDetail (INT-01).</p>

<p id="root-vendor-needed-for-cross-suite-phpunit">INT-01..INT-03 verify against `./vendor/bin/phpunit` at the workspace root, but TASK.md does not list `+m composer.json` because the root `composer.json` has no per-row owner. Adding `phpunit/phpunit: ^11.5` as a root `require-dev` + running `composer install` is implicitly required to satisfy the verify command — treat it the same way as the controllers-require-bootstrap-registration pattern. Don't add `task-tracker/admin` / `task-tracker/public` as root requires; the integration `tests/integration/bootstrap.php` resolves both namespaces by requiring each app's `vendor/autoload.php` directly. Composer's PSR-4 ClassLoader is idempotent across these two registrations because the namespaces are disjoint (Admin vs Public) and the shared `task-tracker/core` snapshot installed in each app's vendor points at identical files.</p>
